Research writing workspace

Use Chuvadi as a project-centered research assistant.

Chuvadi combines a browser LaTeX editor, a backend TeX compiler, GitHub-backed project storage, project-scoped memory, and AI workflows for reviewing, revising, rebutting, and improving research papers.

Recommended mental model: a project is more than a folder of .tex files. It is a GitHub workspace plus saved reports, revision history, and project memory.
Quick start
  • Create or open a project from the left Project panel.
  • Set the root file, usually main.tex.
  • Compile with the backend compiler.
  • Run AI review/rebuttal workflows from the right panel.
  • Save Project to commit source files, reports, and workspace state to GitHub.

Overview

The main editor is designed around a three-panel workflow:

Left panelProject actions, project workspace state, and the file tree.
Center panelThe active LaTeX source editor and PDF/draft preview.
Right panelAI tools, reviewer/rebuttal workflows, literature tools, settings, diagnostics, and reports.

The top bar links to the standalone companion apps: Kalvi, Review Corpus, Value/Action Lab, and this Help page.

Projects and memory

A Chuvadi project should be treated as the unit of work for a paper or research document. When a GitHub project is loaded, Chuvadi restores the source files and uses the project identity to restore project-scoped memory.

A project can include:

  • LaTeX source files such as main.tex, refs.bib, style files, and figures.
  • Saved reports under paths such as /reviews/.
  • Workspace metadata under .latexai/ or latexai/ when present.
  • Backend memory about reviewer concerns, notation, successful edits, failed edits, citations, and agent runs.
Switching projects: when you open a different project, the file tree, project identity, reports, and restored memory should switch with it. Old project memory should not leak into the new project unless you explicitly import it.

Project actions

ActionWhat it does
New ProjectCreates a fresh GitHub-backed project with default LaTeX files and a fresh project memory scope.
Open ProjectOpens an existing project in its last saved state. Project files, reports, and memory are restored for the selected workspace.
Save ProjectCommits the current source files and project artifacts to GitHub. Use the save-comment field to describe the change.
Import ProjectImports an existing set of files. If the imported files do not contain Chuvadi metadata or memory, they start with empty project memory.
Export zipDownloads a zip of the current project files.
Revert versionAllows returning to an older GitHub revision when supported by the GitHub backend.

Use the save comment field next to Save Project like a Git commit message, for example: Added rebuttal edits and fixed theorem statement.

Project files

The file tree shows the files in the current project. Select a file to edit it. Common actions include rename, delete, and download. Folder and file insertion actions create new project entries before the next save.

  • Use Insert file for new .tex, .bib, style, note, or asset files.
  • Use Insert folder to organize sources, notes, figures, or reviews.
  • Use the small download icon beside a file when you only want that one file.
  • Use Export zip when you want the whole project.

Compile and preview

Chuvadi now uses the backend compiler as the main compile path. The local browser WASM and TeXlyre compiler options are intentionally hidden from the normal UI.

Backend URL

The compile endpoint should end in:

.../api/lumina/latex/compile

The backend status endpoint should end in:

.../api/lumina/latex/status

Root file

Set the root file to the main LaTeX entry point, usually main.tex. If the wrong root file is selected, compilation may fail even when individual files are valid.

Style files and packages

If a project uses style files such as conference templates, make sure those files are present in the repo or installed in the backend TeX Live image. Recent backend stages include broader TeX Live support for common packages such as MnSymbol.

AI workflows

The right panel contains AI workflows for paper improvement. The exact buttons may change by stage, but the main patterns are:

  • Reviewer/rebuttal simulator: generates reviewer-style critiques, rebuttals, and synthesized revision suggestions.
  • Competitive review: compares the paper against nearby work or benchmark papers and suggests changes.
  • Devil’s Advocate debate: runs adversarial critique and defense rounds to expose weaknesses.
  • Editor/revision workflows: insert suggested LaTeX edits using \laiold and \lai style markup when enabled.
Best practice: run AI workflows after compiling successfully. Save Project after accepting important changes so reports and source edits are committed together.

Kalvi

Kalvi is the standalone literature assistant for managing and searching a literature collection. Use it when you want to ingest papers, retrieve related work, build citation context, or gather evidence before running a paper review workflow.

Typical use:

  1. Open Kalvi from the top bar.
  2. Ingest or search papers relevant to your current project.
  3. Return to the editor and enable literature/knowledge context in workflows that support it.

Review Corpus

The Review Corpus app is for working with review/rebuttal examples and reviewer-style corpora. Use it to inspect examples, build review context, and support reviewer simulation workflows.

Value/Action Lab

The Value/Action Lab is a standalone experimental app for testing action-selection, feedback, and learning policies used by agentic workflows. It is mainly useful when developing or debugging the agent strategy layer.

Settings and diagnostics

Settings are intentionally focused on the backends that are currently used:

  • Backend compiler: compile URL, status URL, root file, engine, timeout, and shell-escape safety.
  • AI backend: provider/model routing and AI endpoint configuration.
  • Memory backend: project memory restore and retrieval configuration.
  • GitHub backend: project open/save/revert operations.

Use Copy diagnostics when reporting a problem. It includes the active project, root file, backend URLs, compile status, memory status, and stage identifiers.

Troubleshooting

Compile says “Load failed”

This usually means the browser could not complete the backend request, or the backend crashed before returning a normal JSON error. Check the compile backend URL, CORS, and Cloud Run logs.

A package is missing

If the log says a file such as something.sty is missing, either add that style file to the project or install the corresponding TeX Live package in the backend Docker image.

GitHub project does not open

Test the GitHub backend, check that the token can access the repo, and verify that the project backend stage is current. Private repositories do not need to be public, but the backend token needs access.

Memory or reports look stale

Confirm the Project Workspace card shows the correct repository, branch, root path, project ID, and paper ID. Save reports under /reviews/ and commit them with Save Project.

Suggested end-to-end workflow

  1. Open Project or create a New Project.
  2. Confirm the Project Workspace card shows the correct project and memory state.
  3. Set or confirm the root file.
  4. Compile until the PDF is clean enough to inspect.
  5. Run reviewer/rebuttal or competitive-review workflows.
  6. Review generated reports under /reviews/.
  7. Apply selected edits to source files.
  8. Compile again.
  9. Write a save comment and press Save Project.
